C1 · 编译期化简：常量折叠、强度削减、coalesce 与循环外提

CuTe 的 layout 代数不会在 GPU 上运行：shape 和 stride 是静态整数时，C++ 编译器在实例化模板的那一刻就把整套“TV layout → tile 坐标 → gmem offset”的计算折叠成几条移位、按位与和加法。这道题把运行例子里一个线程的 copy 地址写成表达式树，亲手做常量折叠、强度削减、coalesce 和循环不变量外提，再和真实 clang 编出来的汇编对照。

题面速览

  • 背景知识：先读 Layout Algebra 与编译 的“三层要分开”。运行例子见 从零设计：A[64,64] 行主序，CTA tile 32×16，128 个线程，ThrLayout (32,4):(4,1)、ValLayout (1,4)。
  • 在体系里的位置：三层里的第一层“编译期 Layout 处理”：常量折叠、映射复合、规范化（coalesce）、推导访问属性。真实 CuTe 算出的 TV layout 是 ((_4,_32),(_4,_1)):((_128,_1),(_32,_0))（由 make_tiled_copy 生成），offset 表在 tests/golden/c1_static_folding.json。
  • 你要实现：layout_expr、idx2crd_expr、copy_offset_expr、fold、strength_reduce、simplify、count_ops、coalesce_flat、layout_index_expr、hoist。C、V、evaluate、pretty 已给出。
  • 关键规则：
    1. 表达式是元组：('c', n)、('v', name)、(op, a, b)；变量都是非负整数。
    2. idx2crd_expr 用 colex，最后一个模式不取模（和 CuTe 一样）。
    3. fold 做到不动点：常量求值、x*1、x+0、(x*c1)*c2、(x//c1)//c2、常量放右边。
    4. strength_reduce 只处理 2 的幂：*2^n → <<n、//2^n → >>n、%2^n → &(2^n−1)。
    5. count_ops 对结构相同的子表达式只算一次（模拟 CSE），常量子树不算。

验收要点：layout_expr / idx2crd_expr 的结构 · 4 轮 k 的静态和动态 offset 与真实 CuTe 逐个相等（各 512 个，化简前后都要相等）· 静态化简后没有 *、//、%，正好是 {+:4, <<:4, &:3, >>:2} · 动态保留 4 个 *、1 个 //、1 个 % · 折叠与强度削减的每条规则 · CSE 计数 · coalesce 能消掉表达式化简看不出来的恒等函数 · k 循环外提出步长 16（动态时是 bk）· 非线性时报错 · 300 个随机表达式化简前后值相同 · 真实汇编里静态版本没有乘除、动态版本有。

第一次出现的术语
  • 常量折叠（constant folding）：编译期就能算出的子表达式直接换成结果。
  • 强度削减（strength reduction）：把贵的运算换成便宜的等价运算，例如乘以 8 换成左移 3 位。
  • CSE（Common Subexpression Elimination）：相同的计算只做一次。
  • 循环不变量外提（loop-invariant code motion / hoisting）：循环里每轮都一样的部分挪到循环外，循环内只做增量。
  • SASS：NVIDIA GPU 的真实机器指令；PTX：NVIDIA 的虚拟指令集，由 ptxas 编译成 SASS。

直觉与类比

类比 · 提前印好的快递单

每个线程每一轮都要“算出自己要搬的 4 个元素在全局内存的地址”。如果仓库的货架规格（shape、stride）是写死在合同里的（静态整数），物流公司可以提前把每个快递员的取件单印好：“从 tid·16 + … 号货架开始，每轮往后挪 16 格”，快递员只需要做加法。如果货架规格要到开工那天才告诉你（动态整数），每个快递员每轮都得现场做乘法、除法、取模，才能算出货架号。CuTe 的静态 layout 就是“提前印好的取件单”：抽象本身在编译期被消化掉，这就是文档说的“零成本抽象”的准确含义。

要点 · 三层优化，各管各的

CuTe 的静态 layout 代数（本题：折叠、规范化、合法性检查）、CuTe C++ 模板实例化 / CuTe DSL 的 IR 与 lowering（结构化控制流、硬件语义）、CUDA 后端（PTX → SASS 的指令选择、寄存器分配、调度）。layout 代数提供的是“静态信息和低成本的基础”，最后发出什么指令仍然要看后端。CuTe DSL 也是同一个思路：用 AST rewrite 保留循环和分支，用 tracing 捕获算术和 tensor 操作，再 JIT 编译并缓存（dsl_code_generation.rst、dsl_jit_caching.rst）；静态和动态 layout 的区别见 dsl_dynamic_layout.rst。

逐步演示

▶ 一个线程的 copy 地址：从 18 个运行时运算到 13 个廉价运算
1. 构造

按 CuTe 的顺序写：tc = idx2crd(tid, (4,32))、vc = idx2crd(v, (4,1))，idx = tc·(128,1) + vc·(32,0)，(m, kk) = idx2crd(idx, (32,16))，offset = m·64 + (k·16 + kk)·1。没化简时 CSE 后有 {+:5, *:7, %:3, //:3}。

2. 常量折叠

(tid//4)*1 → tid//4、(v//4)*0 → 0、(...)*1 → ...：剩 {+:4, *:4, %:3, //:2}。结果是 ((((tid%4)*128 + tid//4 + (v%4)*32) % 32) * 64) + (k*16 + (... // 32))。

3. 强度削减

所有乘数、除数、模数都是 2 的幂：*128 → <<7、//4 → >>2、%32 → &31、*64 → <<6。剩 {+:4, <<:4, &:3, >>:2}，没有一个乘法、除法或取模。用 golden 验证：tid=0, v=0, k=1 → 16，tid=1 → 20，tid=4 → 80，tid=127, v=3 → 2015。

4. 循环外提

hoist(e, 'k') 得到 step = 16：K 循环里每轮只需要把基地址加 16，base 只在循环外算一次（{+:3, <<:3, &:3, >>:2}）。这正是真实 kernel 里“每个 k-tile 指针前进 BK 个元素”。

5. 动态版本

同样的结构，但 stride 是 4*bm、bm、ld，shape 是 (bm, bk)：化简后还剩 {*:4, //:1, %:1, &:2, <<:1, >>:1, +:4}：编译器不知道 bm 是 32，就只能真的去乘、真的去除。外提仍然成立，只是步长变成 bk。

易错点

  • colex 写成行主序。 CuTe 的第一个模式变化最快：idx2crd(i, (4,8,2)) = (i%4, (i//4)%8, i//32)。测试 test_idx2crd_colex_last_mode_not_wrapped 抓这个。
  • 最后一个模式也取模。 CuTe 不对最后一个模式取模，越界的索引沿最后一个 stride 走；idx2crd(70, (4,8,2)) 是 (2,1,2) 而不是 (2,1,0)。
  • fold 只做一遍。 ((x*2)*4)*1 需要多轮；测试 test_fold_identities_and_constant_chains。
  • 对非 2 的幂也做强度削减。 x*6 不能换成移位（可以拆成移位加法，但不在本题规则里）；测试 test_strength_reduce_only_powers_of_two。
  • count_ops 不去重。 idx 在 m 和 kk 里各出现一次，不去重会把静态版本数成 >>:3；测试要求 {+:4, <<:4, &:3, >>:2}。
  • 以为“除以 2 的幂就是右移”对 C++ int 永远成立。 本题假设非负；真实 C++ 用有符号 int，编译器要插入符号修正（见下面汇编里的 csel、csneg）。用 uint32_t 或让编译器知道值非负，才能得到纯移位。

关键问题

  1. 为什么静态 TV layout 里 v 的第二个模式是 (4,1):(32,0) 中的 1:0？它在表达式里变成了什么，fold 之后去哪了？
  2. (tid % 4) * 128 + tid // 4 这一步在算什么？为什么不是 tid？
  3. 为什么 simplify 化简不掉 (i & 31) + ((i >> 5) << 5)，而 coalesce_flat 一眼就能看出它是 i？
  4. 动态版本外提之后步长是 bk。如果 bk 也是静态的而 ld 是动态的，哪些乘法会消失？
L2思路拆解与常见坑拆解与常见坑（中度剧透）
  • idx2crd_expr：维护一个前缀积表达式 prefix（开始是“没有”）；第 i 个坐标是 idx // prefix（i=0 时就是 idx），不是最后一个就再 % s_i；然后 prefix *= s_i（两边都是常量时直接乘成常量）。
  • fold：写一个“处理一个节点”的函数：先递归处理两个孩子，再按规则改写这个节点；外面套一个 while，直到不再变化。
  • strength_reduce：同样递归；判断 2 的幂用 n & (n-1) == 0，指数用 n.bit_length() - 1。
  • count_ops：一个 seen 集合记录已经计过的子树（元组可以直接放进 set），跳过常量子树（不含任何变量的子树）。
  • hoist：先 simplify，把 + 树展平成项列表；含 k 的项必须是 k、k*c 或 k<<n，把它们的系数加起来就是 step。
L3关键问题的答案几乎是答案（重度剧透）
答案
  1. 每个线程只有 4 个值，ValLayout (1,4) 在 TV layout 里变成 (4,1)：第一个模式 4 是“4 个连续的 K 元素”（stride 32，因为 tile 是 colex 的 32×16，K 方向每走一步跨 32 个索引），第二个模式尺寸 1、stride 0 是占位。表达式里它是 (v // 4) * 0，fold 第一轮就把它变成 0 并消掉。
  2. 这是 ThrLayout (32,4):(4,1) 的逆映射：线程号 tid = m_thr·4 + k_thr，所以 k_thr = tid % 4、m_thr = tid // 4；再乘以 tile 内 colex 索引的 stride（k_thr 对应 4 个 K 元素 = 128 个索引，m_thr 对应 1 个索引）。CuTe 用 right_inverse 自动算出了这个逆。
  3. 表达式化简只看局部结构，不知道 i & 31 和 (i >> 5) << 5 恰好是 i 的低位和高位、相加没有进位重叠；layout 层面的 coalesce 看的是“前一个模式走完正好接上后一个模式”（32·1 == 32），这是一个关于整个函数的全局事实。这就是为什么 CuTe 在代数层面先规范化，而不是指望后端去证明。
  4. k * bk 变成 k << 4，(...) // bm 和 % bm 仍然在（bm 动态），m * ld 仍然是乘法。静态信息越多，后端越能把乘除换成移位；这也是 CUTLASS 把 tile 大小都做成模板参数、把问题尺寸（M、N、K、ld）留给运行时的原因。

CuTe 的 layout 代数本身不在 GPU 上运行。一个线程算地址 offset = L(tid, v, k) 时，如果 shape 和
stride 都是静态整数（Int<N>），C++ 编译器在实例化模板时就能把整套 layout 代数折叠成几条移位、与运算和加法；如果它们是运行时值，乘法和除法就会留在机器码里。这道题用一个小小的表达式树把
这个过程亲手做一遍：先把“线程的 copy 地址”写成表达式，再依次做常量折叠、强度削减、
coalesce 和循环不变量外提，最后数一数还剩多少运行时运算。

运行例子（与仓库所有题目相同）
    A[64,64] 行主序（K 连续），CTA (0,0) 的 tile (BM,BK) = (32,16)，K 方向 4 轮。
    TiledCopy：ThrLayout (32,4):(4,1)，ValLayout (1,4)；CuTe 算出的 S TV layout 是

    tile 内索引 -> (m, kk)：Layout (32,16) 的 colex 坐标；gmem offset = m*64 + k*16 +kk。

表达式（全部是 Python 元组，结构化比较）
    ('c', n)              常量 n（int）
    ('v', name)           运行时变量（tid、v、k，或动态 shape/stride 的名字，如 'bm'）
    (op, a, b)            op ∈ {'+', '*', '//', '%', '<<', '>>', '&'}；<<, >>, & 的右操作数是常量

    idx2crd_expr(idx, shape) -> tuple     colex 分解（CuTe 约定）：c_0 = idx % s_0，
                                          c_i = (idx // (s_0…s_{i-1})) % s_i，最后一个模式不取模：
                                          c_{n-1} = idx // (s_0…s_{n-2})。shape 元素可以是 int 或 str；
                                          前缀积按从左到右的 '*' 构造（静态部分直接相乘成常量）。
                                          rank 1 时返回 (idx,)。

                                            vc = idx2crd_expr(V('v'),   (4, 1))
                                            idx = layout_expr(TV_STRIDE, tc + vc)

                                            两边都是常量 → 计算出结果；

                                          静态扁平 layout 的 coalesce（A3 的规则）：去掉尺寸 1 的模式，
                                          s_i*d_i == d_{i+1} 时合并相邻模式；结果仍是 tuple（至少一个模式，
                                          全是尺寸 1 时返回 ((1,), (0,))）。
    layout_index_expr(idx, shape, stride, coalesce=False) -> e
                                          layout_expr(stride, idx2crd_expr(idx, shape))；coalesce=True 时
                                          先 coalesce_flat 再构造。
    hoist(e, loop_var) -> (base, step)    e 必须是 loop_var 的一次函数：e == base + loop_var*step，
                                          base 和 step 都不含 loop_var（先 simplify再分解；
                                          loop_var 只能出现在 '+' 的项里，作为 x、x*c或 x<<n）。
                                          不满足时抛 ValueError。返回的 base、step 都已simplify。
"""
from __future__ import annotations


def C(n: int):
    """常量节点。"""
    return ("c", int(n))


def V(name: str):
    """运行时变量节点。"""
    return ("v", name)


def evaluate(e, env: dict) -> int:
    """在 env 下求值（非负整数语义）。"""
    tag = e[0]
    if tag == "c":
        return e[1]
    if tag == "v":
        return env[e[1]]
    a, b = evaluate(e[1], env), evaluate(e[2], env)
    if tag == "+":
        return a + b
    if tag == "*":
        return a * b
    if tag == "//":
        return a // b
    if tag == "%":
        return a % b
    if tag == "<<":
        return a << b
    if tag == ">>":
        return a >> b
    if tag == "&":
        return a & b
    raise ValueError(f"unknown op {tag!r}")


def pretty(e) -> str:
    """中缀打印。"""
    tag = e[0]
    if tag == "c":
        return str(e[1])
    if tag == "v":
        return e[1]
    return f"({pretty(e[1])} {tag} {pretty(e[2])})"


def _s(x):
    # shape / stride 元素：int → 常量，str → 变量
    return C(x) if isinstance(x, int) else V(x)


def layout_expr(stride, coord):
    """Σ coord_i * stride_i，从左到右累加。"""
    if len(stride) != len(coord):
        raise ValueError("stride and coord must have the same length")
    acc = None
    for c, d in zip(coord, stride):
        term = ("*", c, _s(d))
        acc = term if acc is None else ("+", acc, term)
    return acc


def idx2crd_expr(idx, shape):
    """colex 分解；最后一个模式不取模（CuTe 的约定）。"""
    n = len(shape)
    if n == 1:
        return (idx,)
    out = []
    prefix = None                      # 前缀积表达式（None 表示 1）
    for i, s in enumerate(shape):
        q = idx if prefix is None else ("//", idx, prefix)
        out.append(q if i == n - 1 else ("%", q, _s(s)))
        if prefix is None:
            prefix = _s(s)
        elif prefix[0] == "c" and isinstance(s, int):
            prefix = C(prefix[1] * s)  # 静态部分直接相乘
        else:
            prefix = ("*", prefix, _s(s))
    return tuple(out)


TV_STRIDE_STATIC = (128, 1, 32, 0)


def copy_offset_expr(static: bool = True):
    """运行例子：线程 tid 的第 v 个值在第 k 轮的 gmem offset。"""
    if static:
        tv_stride, BM, BK, LD = TV_STRIDE_STATIC, 32, 16, 64
        kBK = ("*", V("k"), C(16))
    else:
        tv_stride = (("*", C(4), V("bm")), 1, "bm", 0)
        BM, BK, LD = "bm", "bk", "ld"
        kBK = ("*", V("k"), V("bk"))
    tc = idx2crd_expr(V("tid"), (4, 32))
    vc = idx2crd_expr(V("v"), (4, 1))
    # layout_expr 只接受 int/str stride；动态的 4*bm 已经是表达式，单独处理
    coords = tc + vc
    acc = None
    for c, d in zip(coords, tv_stride):
        term = ("*", c, d if isinstance(d, tuple) else _s(d))
        acc = term if acc is None else ("+", acc, term)
    idx = acc
    m, kk = idx2crd_expr(idx, (BM, BK))
    return layout_expr((LD, 1), (m, ("+", kBK, kk)))


def _is_c(e):
    return e[0] == "c"


def _fold_node(e):
    tag = e[0]
    if tag in ("c", "v"):
        return e
    a, b = _fold_node(e[1]), _fold_node(e[2])
    if _is_c(a) and _is_c(b):
        return C(evaluate((tag, a, b), {}))
    # 常量放右边（只对交换的 + 和 *）
    if tag in ("+", "*") and _is_c(a) and not _is_c(b):
        a, b = b, a
    if tag == "*":
        if b == C(0):
            return C(0)
        if b == C(1):
            return a
        if _is_c(b) and a[0] == "*" and _is_c(a[2]):        # (x*c1)*c2
            return ("*", a[1], C(a[2][1] * b[1]))
    if tag == "+":
        if b == C(0):
            return a
        if _is_c(b) and a[0] == "+" and _is_c(a[2]):        # (x+c1)+c2
            return ("+", a[1], C(a[2][1] + b[1]))
    if tag == "//":
        if b == C(1):
            return a
        if a == C(0):
            return C(0)
        if _is_c(b) and b[1] > 0 and a[0] == "//" and _is_c(a[2]) and a[2][1] > 0:# (x//c1)//c2
            return ("//", a[1], C(a[2][1] * b[1]))
    if tag == "%":
        if b == C(1) or a == C(0):
            return C(0)
    return (tag, a, b)


def fold(e):
    """常量折叠 + 恒等化简，直到不动点。"""
    # 为什么要迭代：一次自底向上只能看到“子节点已经化简后的样子”，
    # 像 ((x*2)*4)*1 这样的链需要多轮才能完全合并。
    while True:
        n = _fold_node(e)
        if n == e:
            return e
        e = n


def _pow2(n: int):
    return n >= 2 and (n & (n - 1)) == 0


def strength_reduce(e):
    """乘、除、模 2 的幂 → 移位与按位与。"""
    tag = e[0]
    if tag in ("c", "v"):
        return e
    a, b = strength_reduce(e[1]), strength_reduce(e[2])
    if _is_c(b) and _pow2(b[1]):
        n = b[1].bit_length() - 1
        if tag == "*":
            return ("<<", a, C(n))
        if tag == "//":
            return (">>", a, C(n))       # 只因为变量都非负才合法；有符号 int 需要修正
        if tag == "%":
            return ("&", a, C(b[1] - 1))
    return (tag, a, b)


def simplify(e):
    """fold 与 strength_reduce 交替到不动点。"""
    while True:
        n = strength_reduce(fold(e))
        if n == e:
            return e
        e = n


def count_ops(e) -> dict:
    """结构不同的运行时子表达式按 op 计数（模拟 CSE）。"""
    seen = set()
    counts: dict = {}

    def has_var(x):
        return x[0] == "v" or (x[0] not in ("c", "v") and (has_var(x[1]) or has_var(x[2])))

    def walk(x):
        if x[0] in ("c", "v") or x in seen or not has_var(x):
            return
        seen.add(x)
        counts[x[0]] = counts.get(x[0], 0) + 1
        walk(x[1])
        walk(x[2])

    walk(e)
    return counts


def coalesce_flat(shape, stride):
    """静态扁平 layout 的 coalesce。"""
    modes = [(s, d) for s, d in zip(shape, stride) if s != 1]
    if not modes:
        return (1,), (0,)
    out = [modes[0]]
    for s, d in modes[1:]:
        ps, pd = out[-1]
        if ps * pd == d:                 # 前一个模式走完正好接上
            out[-1] = (ps * s, pd)
        else:
            out.append((s, d))
    return tuple(s for s, _ in out), tuple(d for _, d in out)


def layout_index_expr(idx, shape, stride, coalesce: bool = False):
    """layout(idx) 的表达式；coalesce=True 先合并模式。"""
    if coalesce:
        shape, stride = coalesce_flat(shape, stride)
    return layout_expr(stride, idx2crd_expr(idx, shape))


def _terms(e):
    # 把 '+' 树展平成项列表
    if e[0] == "+":
        return _terms(e[1]) + _terms(e[2])
    return [e]


def _contains(e, name):
    if e[0] == "v":
        return e[1] == name
    if e[0] == "c":
        return False
    return _contains(e[1], name) or _contains(e[2], name)


def hoist(e, loop_var: str):
    """e == base + loop_var*step，base、step 不含 loop_var。"""
    e = simplify(e)
    base, step = None, None
    for t in _terms(e):
        if not _contains(t, loop_var):
            base = t if base is None else ("+", base, t)
            continue
        # 允许的形式：x、x*c、x<<n（x 就是 loop_var，c 不含 loop_var）
        if t == V(loop_var):
            s = C(1)
        elif t[0] == "*" and t[1] == V(loop_var) and not _contains(t[2], loop_var):
            s = t[2]
        elif t[0] == "<<" and t[1] == V(loop_var) and _is_c(t[2]):
            s = C(1 << t[2][1])
        else:
            raise ValueError(f"term {pretty(t)} is not linear in {loop_var}")
        step = s if step is None else ("+", step, s)
    return simplify(base if base is not None else C(0)), simplify(step if step is not None else C(0))

面试官追问 & 对照源码

  • 本题的 v % 4 在 v ∈ [0,4) 时其实是恒等的，真实编译器会把 for v in 0..3 展开，v 变成常量。CuTe 里这类展开靠 CUTE_UNROLL 和静态的 size(...)；给 simplify 加一个“值域分析”，你能消掉哪些运算？
  • CuTe 的 composition 先做 coalesce_x 再做分模除法（composition_impl）。为什么它要在“组合之前”而不是“组合之后”规范化？
  • 本题的化简能告诉你“这个配置的地址计算便宜”，但不能告诉你“这个配置最快”。后者需要什么（见 E2）？
  • 在 CuTe DSL 里，cutlass.Constexpr 参数在编译期求值、不进入运行时参数（dsl_jit_caching.rst）。它和 C++ 的 Int<N> 在“让编译器折叠”这件事上是同一种机制吗？JIT 缓存的 key 应该包含哪些东西？
  • 有符号除法的修正指令（csel、csneg）在 GPU 上对应什么？为什么很多 CUDA kernel 把线程号和循环变量声明成 unsigned 或用 __builtin_assume？

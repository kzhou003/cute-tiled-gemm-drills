直觉与类比

类比 · 先用最普通的工人把流水线跑通

Tensor Core 是专用冲压机，CUDA core 是普通机床。F1 只用普通机床，但车间的组织方式已经是最终的样子：订单（C）按 128×128 切给小组（CTA）；每轮从仓库搬一小箱料（A、B 各 128×8）上工作台（SMEM），搬的时候 256 个工人按“搬运表”（ThrA ）分工；然后每个工人按“加工表”（ThrC ）从工作台取料，在自己的工具台（寄存器）上累加 8×8 = 64 个零件。后面四题只是把机床换成冲压机、把一次一箱换成流水线。

▶ 从全局张量到写回
1. 全局张量：只是指针加 layout

make_tensor(make_gmem_ptr(A), make_shape(M, K), make_stride(K, Int<1>{})) 不搬任何数据，它只是说“A 是一个 M×K、K 方向 stride 为 1 的张量”。动态的 M、N、K 和静态的 Int<1> 可以混用：静态的部分在编译期就被折叠掉（Track C）。

2. ① local_tile：这个 CTA 看哪一块

local_tile(mA, make_shape(BM, BN, BK), make_coord(blockIdx.x, blockIdx.y, _), Step<_1, X, _1>{})。Step<_1, X, _1> 说“A 只用 tiler 的 M、K 两维”；坐标里的 _ 说“K 方向不固定，保留成最后一维”。结果 gA 的形状是 (128, 8, K/8)：第三维就是 k-tile 编号。

3. ② local_partition：每个线程拿哪几个

local_partition(gA, ThrA{}, threadIdx.x) 把 (128,8) 按 ThrA 的形状 (32,8) 切块，线程 t 在每一块里拿 ThrA⁻¹(t) 那个位置——4 个元素，形状 (4, 1, k)。计算分工用投影：local_partition(sA, ThrC{}, t, Step<_1, X>{}) 只按 ThrC 的“行”去分 sA，所以线程 t 拿到 8 整行（8 × BK）。

4. ③ K 循环：搬、等、算、等

copy(tAgA(_, _, kt), tAsA) 逐元素搬（BF16 → float 的转换就发生在这里），__syncthreads()，gemm(tCsA, tCsB, tCrC) 做 (8,8) += (8,8)·(8,8)ᵀ 的外积累加，全是 FFMA，再 __syncthreads()。

5. 写回

copy(tCrC, tCgC)：每个线程把自己的 64 个累加器写到 C 的 64 个位置。它们按 16 的步长散开，所以每个 warp 的一条 store 写的是 32 个不连续的 float——这是 F1 慢的原因之一。

L2思路拆解拆解与常见坑（中度剧透）

① 三次 local_tile ，只差 Step ：A 是 Step<_1, X, _1> ，B 是 Step<X, _1, _1> ，C 是 Step<_1, _1, X> 。② 搬运用 local_partition(g, Thr, threadIdx.x) ；计算用带投影的版本：sA 按 ThrC 的行（Step<_1, X> ）、sB 按列（Step<X, _1> ）、gC 两维都用（Step<_1, _1> ）；累加器 make_tensor_like(tCgC) 后 clear 。③ 循环次数是 size<2>(tAgA) 。

L3关键问题的答案几乎是答案（重度剧透）

为什么需要两个 __syncthreads？

第一个：所有线程的 copy 都写进 SMEM 之后才能开始算（别的线程搬的数据你也要用）。第二个：所有线程都算完之后，下一轮才能覆盖 SMEM。去掉第二个，快的 warp 会在慢的 warp 还在读 sA 时把它覆盖掉——结果偶尔错、而且和运行次数有关，是最难查的那一类 bug。

"""F1 · 第一个真实的 CuTe kernel：local_tile + local_partition + SMEM，用 CUDA core 算 — reference solution.

这一题有两部分：
1. **GPU 部分**（`f1_simt_cute_gemm.cu`）：用真实 CuTe 写一个 SIMT（FFMA）的 tiled GEMM，在 RTX 5090 上跑通、对拍、计时。
2. **主机部分**（本文件）：把 kernel 里每个 `local_partition` 的结果先用整数算出来——哪个线程搬哪几个元素、
   哪个线程累加哪 64 个输出——并和真实 CuTe 的输出（oracle/f1_simt_cute_gemm.cpp → tests/golden）对拍。
   这样在没有 GPU 的机器上也能确认自己对 kernel 的理解是对的。

配置（和 .cu 一致，对照 CUTLASS examples/cute/tutorial/sgemm_1.cu）
- A: M×K、B: N×K（都按 K 连续），C: M×N（按 N 连续），C = A·Bᵀ。
- CTA tile (BM, BN, BK) = (128, 128, 8)，256 线程。
- 搬运：ThrA = ThrB = (32,8):(8,1)——线程 t 在线程布局里的坐标是 (t // 8, t % 8)。
  local_partition(tile, ThrA, t) 把 (128,8) 的 tile 按 (32,8) 切，线程 t 拿每一块里的同一个位置：
  (t // 8 + 32·i, t % 8)，i = 0..3（按 i 的顺序）。
- 计算：ThrC = (16,16):(1,16)——线程 t 的坐标是 (t % 16, t // 16)。
  线程 t 累加 C tile 的 (t % 16 + 16·a, t // 16 + 16·b)，a, b = 0..7；顺序是 a 先变（列主序，index = a + 8·b）。
  它读 sA 的行 t % 16 + 16·a（Step<_1, X> 只按行投影），读 sB 的行 t // 16 + 16·b。

计数
- global_bytes(M, N, K)：所有 CTA 从全局内存读的字节数 = CTA 数 × k-tile 数 × (BM + BN)·BK·2。
  （BF16 每元素 2 字节；不考虑 L2 命中——这是“L2→SM”的流量。）
- ffma_per_thread(K)：每个线程做的 FFMA 次数 = 8·8·K。
- smem_loads_per_ffma()：gemm(tCsA, tCsB, tCrC) 每个 k 读 8 个 a + 8 个 b，做 64 次 FFMA → 16/64。

API
    BM, BN, BK, THREADS                                    given
    cta_grid(M, N) -> (int, int)                           M、N 不是 128 的倍数时 ValueError
    copy_coords(t) -> [(m, k), ...]                        长度 4
    c_coords(t) -> [(m, n), ...]                           长度 64，列主序
    a_rows(t) -> [m, ...]                                  长度 8：线程 t 计算时读的 sA 行
    b_rows(t) -> [n, ...]                                  长度 8
    global_bytes(M, N, K) -> int
    ffma_per_thread(K) -> int
    smem_loads_per_ffma() -> float
"""
from __future__ import annotations

BM, BN, BK, THREADS = 128, 128, 8, 256


def _check_t(t: int) -> None:
    if not 0 <= t < THREADS:
        raise ValueError(f"thread {t} out of range [0, {THREADS})")


def cta_grid(M: int, N: int) -> tuple:
    if M <= 0 or N <= 0 or M % BM or N % BN:
        raise ValueError(f"F1 needs M, N to be positive multiples of {BM}, got {M}x{N}")
    return M // BM, N // BN


def copy_coords(t: int) -> list:
    _check_t(t)
    # ThrA (32,8):(8,1) 的逆：t → (t // 8, t % 8)；tile (128,8) 被切成 4 块 (32,8)，沿 M 排
    return [(t // 8 + 32 * i, t % 8) for i in range(BM // 32)]


def c_coords(t: int) -> list:
    _check_t(t)
    # ThrC (16,16):(1,16) 的逆：t → (t % 16, t // 16)；(128,128) 被切成 8×8 块，列主序遍历
    return [(t % 16 + 16 * a, t // 16 + 16 * b) for b in range(8) for a in range(8)]


def a_rows(t: int) -> list:
    _check_t(t)
    return [t % 16 + 16 * a for a in range(8)]


def b_rows(t: int) -> list:
    _check_t(t)
    return [t // 16 + 16 * b for b in range(8)]


def global_bytes(M: int, N: int, K: int) -> int:
    gm, gn = cta_grid(M, N)
    if K <= 0 or K % BK:
        raise ValueError(f"K must be a positive multiple of {BK}")
    return gm * gn * (K // BK) * (BM + BN) * BK * 2


def ffma_per_thread(K: int) -> int:
    return 8 * 8 * K


def smem_loads_per_ffma() -> float:
    return (8 + 8) / (8 * 8)

// F1 · 第一个真实的 CuTe kernel：local_tile + local_partition + SMEM，用 CUDA core（FFMA）算 — reference solution.
//
// 目的是先熟悉“CuTe 张量”在 GPU 上怎么用，还不碰 Tensor Core：
//   make_tensor(make_gmem_ptr(p), shape, stride)  全局张量（只是指针 + layout，不搬数据）
//   local_tile(mA, tiler, coord, Step<...>)       这个 CTA 的那一块（A1）
//   local_partition(tile, thr_layout, tid)        按线程布局把一块分给各个线程（A2 的“谁搬哪个”）
//   copy(src, dst) / gemm(a, b, c)                逐元素搬运 / 逐元素乘加（UniversalFMA）
// 结构对照 CUTLASS examples/cute/tutorial/sgemm_1.cu（gemm_device L44–L246，gemm_tn L300–L350），区别：
//   BF16 输入（读进 SMEM 时转成 float）、C 是行主序 FP32。
//
// 配置：CTA tile 128×128×8，256 线程。
//   搬运：tA = tB = (32,8) 行主序（相邻 8 个线程读同一行的 8 个 K 元素）
//   计算：tC = (16,16) 列主序，每线程负责 8×8 = 64 个输出，按 16 的步长散开（raked）
// 前提：M % 128 == 0、N % 128 == 0、K % 8 == 0。
//
// 运行：python3 tools/cu_drill.py run solutions/f1_simt_cute_gemm.cu 2048 2048 2048
#include <cute/tensor.hpp>

#include "common.cuh"

using namespace cute;

namespace f1 {

using TA = cute::bfloat16_t;
using TB = cute::bfloat16_t;
using TC = float;

using BM = Int<128>;
using BN = Int<128>;
using BK = Int<8>;
using ThrA = Layout<Shape<_32, _8>, Stride<_8, _1>>;     // (m,k) → 线程号，k 连续
using ThrB = Layout<Shape<_32, _8>, Stride<_8, _1>>;     // (n,k) → 线程号
using ThrC = Layout<Shape<_16, _16>, Stride<_1, _16>>;   // (m,n) → 线程号，m 连续
using SmemA = Layout<Shape<BM, BK>, Stride<BK, _1>>;     // (m,k) → SMEM 下标，k 连续
using SmemB = Layout<Shape<BN, BK>, Stride<BK, _1>>;
constexpr int kThreads = 256;

__global__ __launch_bounds__(kThreads) void gemm_kernel(int M, int N, int K, TA const* A, TB const* B, TC* C) {
  // 全局张量
  Tensor mA = make_tensor(make_gmem_ptr(A), make_shape(M, K), make_stride(K, Int<1>{}));   // (M,K)
  Tensor mB = make_tensor(make_gmem_ptr(B), make_shape(N, K), make_stride(K, Int<1>{}));   // (N,K)
  Tensor mC = make_tensor(make_gmem_ptr(C), make_shape(M, N), make_stride(N, Int<1>{}));   // (M,N)

  // 这个 CTA 的 tile
  // [TODO ①] 用 local_tile 切出这个 CTA 的 gA (BM,BK,k)、gB (BN,BK,k)、gC (BM,BN)
  auto cta_tiler = make_shape(BM{}, BN{}, BK{});
  auto cta_coord = make_coord(blockIdx.x, blockIdx.y, _);
  Tensor gA = local_tile(mA, cta_tiler, cta_coord, Step<_1, X, _1>{});   // (BM,BK,k)
  Tensor gB = local_tile(mB, cta_tiler, cta_coord, Step<X, _1, _1>{});   // (BN,BK,k)
  Tensor gC = local_tile(mC, cta_tiler, cta_coord, Step<_1, _1, X>{});   // (BM,BN)
  // [/TODO]

  // SMEM 存 float：BF16 在搬进来时转换一次，后面的 FFMA 就不用每次再转
  __shared__ float smemA[cosize_v<SmemA>];
  __shared__ float smemB[cosize_v<SmemB>];
  Tensor sA = make_tensor(make_smem_ptr(smemA), SmemA{});   // (BM,BK)
  Tensor sB = make_tensor(make_smem_ptr(smemB), SmemB{});   // (BN,BK)

  // 搬运分工：线程 t 负责 tile 里 (t/8 + 32i, t%8) 这几个元素
  // [TODO ②] 用 local_partition 分出搬运分工 tAgA/tAsA/tBgB/tBsB、计算分工 tCsA/tCsB/tCgC，建寄存器累加器 tCrC 并清零
  Tensor tAgA = local_partition(gA, ThrA{}, threadIdx.x);   // (4,1,k)
  Tensor tAsA = local_partition(sA, ThrA{}, threadIdx.x);   // (4,1)
  Tensor tBgB = local_partition(gB, ThrB{}, threadIdx.x);
  Tensor tBsB = local_partition(sB, ThrB{}, threadIdx.x);

  // 计算分工：按 tC 的行投影分 sA、按列投影分 sB、整体分 gC
  Tensor tCsA = local_partition(sA, ThrC{}, threadIdx.x, Step<_1, X>{});    // (8,BK)
  Tensor tCsB = local_partition(sB, ThrC{}, threadIdx.x, Step<X, _1>{});    // (8,BK)
  Tensor tCgC = local_partition(gC, ThrC{}, threadIdx.x, Step<_1, _1>{});   // (8,8)
  Tensor tCrC = make_tensor_like(tCgC);                                       // (8,8) 寄存器累加器
  clear(tCrC);
  // [/TODO]

  // [TODO ③] K 循环（copy → __syncthreads → gemm → __syncthreads），最后把累加器写回 gC
  int k_tiles = size<2>(tAgA);
  for (int kt = 0; kt < k_tiles; ++kt) {
    copy(tAgA(_, _, kt), tAsA);   // 逐元素：BF16 → float
    copy(tBgB(_, _, kt), tBsB);
    __syncthreads();
    gemm(tCsA, tCsB, tCrC);       // (8,8) += (8,BK) · (8,BK)ᵀ，全部是 FFMA
    __syncthreads();
  }
  copy(tCrC, tCgC);
  // [/TODO]
}

inline void launch(int M, int N, int K, TA const* A, TB const* B, TC* C, cudaStream_t stream = 0) {
  dim3 grid(M / BM::value, N / BN::value);
  gemm_kernel<<<grid, kThreads, 0, stream>>>(M, N, K, A, B, C);
}

}  // namespace f1

int main(int argc, char** argv) {
  auto a = drill::parse(argc, argv);
  if (a.M % 128 || a.N % 128 || a.K % 8) {
    std::printf("{\"ok\": false, \"error\": \"F1 needs M,N %% 128 == 0 and K %% 8 == 0\"}\n");
    return 1;
  }
  std::vector<__nv_bfloat16> hA(size_t(a.M) * a.K), hB(size_t(a.N) * a.K);
  drill::fill_bf16(hA, 1);
  drill::fill_bf16(hB, 2);
  auto* dA = drill::to_device(hA);
  auto* dB = drill::to_device(hB);
  float* dC = nullptr;
  CUDA_CHECK(cudaMalloc(&dC, size_t(a.M) * a.N * sizeof(float)));

  auto go = [&] { f1::launch(a.M, a.N, a.K, reinterpret_cast<f1::TA const*>(dA), reinterpret_cast<f1::TB const*>(dB), dC); };
  go();
  CUDA_CHECK(cudaDeviceSynchronize());
  std::vector<float> got(size_t(a.M) * a.N);
  CUDA_CHECK(cudaMemcpy(got.data(), dC, got.size() * sizeof(float), cudaMemcpyDeviceToHost));
  double err = drill::max_rel_err(got, drill::reference(a.M, a.N, a.K, dA, dB));
  float ms = drill::time_ms(go, a.iters);
  drill::report("f1_simt_128x128x8", a, err, ms);
  return 0;
}
